# Лекция 2. Рекурсия и линейные структуры данных

Дисциплина «Структуры и алгоритмы обработки данных», раздел 1. Темы: рекурсия и стек вызовов, мемоизация, «разделяй и властвуй», амортизированный анализ, динамический массив, связные списки, стек, очередь и дек.

## 1. Рекурсия и стек вызовов

**Определение.** Рекурсивная функция — функция, которая решает задачу, вызывая саму себя для той же задачи меньшего размера; цепочка вызовов заканчивается на базовом случае, ответ для которого известен без рекурсивного вызова.

```python
def factorial(n):
    if n == 0:                    # базовый случай
        return 1
    return n * factorial(n - 1)   # шаг: задача меньше на 1
```

Обязательны оба элемента: **базовый случай** (`factorial(0)` возвращает 1) и **рекурсивный шаг**, уменьшающий задачу (n! = n · (n − 1)!). Без базового случая или без уменьшения задачи вызовы продолжаются, пока не упрутся в предел глубины рекурсии, и программа завершается ошибкой `RecursionError`.

**Определение.** Стек вызовов — область памяти, где лежат кадры всех начатых и ещё не завершённых вызовов; кадр хранит аргументы, локальные переменные и точку возврата. Вызов кладёт кадр на вершину стека, возврат снимает его.

При вычислении `factorial(4)` в стеке одновременно лежат 5 кадров — для аргументов 4, 3, 2, 1 и 0: у `factorial(n)` глубина рекурсии равна n + 1, а дополнительная память — Θ(глубины), то есть Θ(n). В CPython предел глубины по умолчанию — 1000 кадров (`sys.getrecursionlimit()`), и кадр вызывающего кода тоже считается: в Python 3.13 из скрипта `factorial(998)` ещё выполняется, а `factorial(999)` завершается ошибкой `RecursionError`.

Рекурсия называется хвостовой, если рекурсивный вызов — последнее действие функции. Python хвостовую рекурсию не оптимизирует: каждый такой вызов всё равно занимает кадр стека. Поэтому линейные процессы (факториал, сумма, проход по массиву) надёжнее записывать циклом, а глубокую рекурсию — заменять циклом с явным стеком.

**Корректность** доказывают индукцией по размеру входа. База: `factorial(0)` возвращает 1 = 0!. Переход: если factorial(n − 1) = (n − 1)!, то n · factorial(n − 1) = n!.

**Завершение** доказывают через меру — неотрицательное целое число, которое строго уменьшается при каждом рекурсивном вызове (у `factorial` это n). Неотрицательное целое число не может убывать бесконечно, поэтому цепочка вызовов конечна. Типичная ошибка — `factorial(-1)`: вызов проскакивает базовый случай `n == 0`, мера становится отрицательной, и вызовы продолжаются до `RecursionError`.

## 2. Числа Фибоначчи и мемоизация

### Разбор 1. Наивное вычисление чисел Фибоначчи — Θ(φⁿ) вызовов

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

Пусть F(n) — n-е число Фибоначчи (F(0) = 0, F(1) = 1), а C(n) — число вызовов при вычислении fib(n), считая и первый. При n ≥ 2 это первый вызов плюс вызовы в поддеревьях fib(n − 1) и fib(n − 2). Слагаемое «+1» мешает узнать в рекуррентности числа Фибоначчи, поэтому перейдём к D(n) = C(n) + 1:

```
C(0) = C(1) = 1,  C(n) = 1 + C(n−1) + C(n−2)  при n ≥ 2
D(n) = C(n) + 1 = C(n−1) + C(n−2) + 1 + 1
     = (C(n−1) + 1) + (C(n−2) + 1) = D(n−1) + D(n−2)
D(0) = 2 = 2·F(1),  D(1) = 2 = 2·F(2)
```

D(n) и 2·F(n+1) подчиняются правилу «сумма двух предыдущих» и совпадают при n = 0 и n = 1, значит, по индукции совпадают при всех n: **C(n) = 2·F(n+1) − 1**. По формуле Бине F(n) ≈ φⁿ/√5, где φ = (1 + √5)/2 ≈ 1,618, поэтому C(n) ≈ 2·φⁿ⁺¹/√5 = (2φ/√5)·φⁿ ≈ 1,45·φⁿ, то есть C(n) = Θ(φⁿ).

Чтобы получить fib(30) = 832 040, наивная функция делает 2 692 537 вызовов: одни и те же подзадачи решаются снова и снова. Память же Θ(n): в стеке лежит только путь от корня дерева вызовов до текущего вызова — не больше n кадров.

**Определение.** Мемоизация — запоминание результатов функции: при первом вызове с некоторыми аргументами результат сохраняется в кэше, а при повторном вызове с теми же аргументами берётся из кэша без пересчёта.

```python
def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n in memo:
        return memo[n]            # из кэша
    if n < 2:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
```

Подсчитаем все входы в функцию, включая попадания в кэш, — именно так их подсчитывает счётчик заготовки ЛР 2. Каждое значение k = 2, …, n вычисляется один раз, и это вычисление делает два рекурсивных вызова; остальные входы (базовые случаи и попадания в кэш) новых вызовов не порождают. Вместе с первым вызовом число вызовов M(n) = 1 + 2·(n − 1) = 2n − 1 при n ≥ 1: для n = 30 это 59 вызовов против 2 692 537.

Под `functools.lru_cache` тело функции выполняется лишь n + 1 раз (n ≥ 2): попадания в кэш обрабатывает обёртка. Итеративный вариант, который n раз выполняет `a, b = b, a + b`, требует Θ(n) времени и Θ(1) памяти и не упирается в предел глубины.

## 3. Ханойские башни

### Разбор 2. Число ходов в Ханойских башнях — 2ⁿ − 1

На стержне A лежат n дисков разного размера, каждый меньше того, что под ним. Их нужно перенести на стержень C, пользуясь B как вспомогательным; за ход переносится один верхний диск, и класть больший диск на меньший нельзя. Решение: рекурсивно перенести n − 1 верхних дисков на B, самый большой диск одним ходом переложить на C, затем рекурсивно перенести n − 1 дисков с B на C. Пусть T(n) — число ходов. Один диск переносится одним ходом, поэтому T(1) = 1; при n ≥ 2 два рекурсивных переноса по T(n−1) ходов и один ход самым большим диском дают T(n) = 2·T(n−1) + 1:

```
T(n) = 2·T(n−1) + 1 = 4·T(n−2) + 2 + 1 = 8·T(n−3) + 4 + 2 + 1 = …
     = 2ᵏ·T(n−k) + (2ᵏ⁻¹ + … + 2 + 1) = 2ᵏ·T(n−k) + 2ᵏ − 1
k = n − 1:  T(n) = 2ⁿ⁻¹·T(1) + 2ⁿ⁻¹ − 1 = 2ⁿ − 1
```

Для 64 дисков нужно 2⁶⁴ − 1 ≈ 1,8·10¹⁹ ходов: при одном ходе в секунду на это уйдёт около 585 млрд лет.

## 4. «Разделяй и властвуй»

**Определение.** «Разделяй и властвуй» — метод построения алгоритмов: задача разбивается на одну или несколько подзадач того же вида, размер которых в b > 1 раз меньше, подзадачи решаются рекурсивно, а их решения объединяются в решение исходной задачи.

Время работы такого алгоритма описывается рекуррентным соотношением T(n) = a·T(n/b) + f(n), где a — число подзадач, b — во сколько раз подзадача меньше исходной, f(n) — стоимость разделения и объединения. Не путать с «уменьшай и властвуй» (факториал, Ханойские башни): там задача уменьшается на 1, а не делится, и мастер-теорема неприменима.

Мастер-теорема из [Лекции 1](lecture-01-complexity.md) сравнивает f(n) с весом рекурсии n^(log_b a): f(n) полиномиально меньше — случай 1, Θ(n^(log_b a)); того же порядка — случай 2, Θ(n^(log_b a) · log n); полиномиально больше и a·f(n/b) ≤ c·f(n) при некотором c < 1 (условие регулярности) — случай 3, Θ(f(n)).

| Алгоритм | T(n) = | a, b, вес | Случай | Ответ |
| --- | --- | --- | --- | --- |
| Бинарный поиск | T(n/2) + Θ(1) | 1, 2, n⁰ = 1 | 2 | Θ(log n) |
| Поиск со срезами (разбор 3) | T(n/2) + Θ(n) | 1, 2, n⁰ = 1 | 3 | Θ(n) |
| Максимум делением пополам | 2T(n/2) + Θ(1) | 2, 2, n¹ | 1 | Θ(n) |

При поиске максимума делением пополам максимумы двух половин находят рекурсивно, а затем сравнивают между собой. Для числа сравнений S(n) имеем S(1) = 0 и S(n) = S(⌈n/2⌉) + S(⌊n/2⌋) + 1 при n ≥ 2; по индукции S(n) = (⌈n/2⌉ − 1) + (⌊n/2⌋ − 1) + 1 = n − 1 (здесь использовано ⌈n/2⌉ + ⌊n/2⌋ = n) — столько же, сколько у простого прохода. Само по себе деление на части не экономит работу, если каждый элемент всё равно нужно сравнить хотя бы раз. Выигрыш появляется, когда после разделения часть работы отпадает: бинарному поиску из двух половин нужна только одна.

### Разбор 3. Рекурсивный бинарный поиск — Θ(log n)

```python
def search(a, x, lo, hi):
    if lo >= hi:
        return -1
    mid = (lo + hi) // 2
    if a[mid] == x:
        return mid
    if a[mid] < x:
        return search(a, x, mid + 1, hi)
    return search(a, x, lo, mid)
```

Массив `a` отсортирован, первый вызов — `search(a, x, 0, len(a))`, диапазон — полуинтервал [lo, hi). Инвариант: если x есть в массиве, он лежит в `a[lo:hi]`. Каждый вызов за Θ(1) вдвое сужает диапазон: T(n) = T(n/2) + Θ(1) = Θ(log n).

Правдоподобная на вид версия, которая отвечает только `True` или `False` и передаёт в рекурсию срез `a[mid + 1:]` или `a[:mid]`, тоже проходит тесты, но каждый срез копирует половину массива:

```
T(n) = T(n/2) + c·n = T(n/4) + c·n/2 + c·n = …
     = c·(n + n/2 + n/4 + … + 1) < c·n·(1 + 1/2 + 1/4 + …) = 2c·n
```

Уже первый уровень стоит c·n, поэтому T(n) = Θ(n): логарифмический поиск стал линейным. Это случай 3 мастер-теоремы, и условие регулярности выполнено: f(n/2) = ½·f(n). Память тоже Θ(n): в самой глубокой точке одновременно живут срезы длиной n/2, n/4, …, 1.

## 5. Динамический массив и амортизированная стоимость

**Определение.** Динамический массив — массив переменного размера: size элементов лежат подряд в буфере из capacity ячеек (size ≤ capacity); когда буфер заполнен, его заменяют буфером большей ёмкости и копируют туда элементы.

Если size < capacity, `append` просто записывает элемент — Θ(1). Иначе создаётся буфер вдвое большей ёмкости, в него копируются size элементов и выполняется запись — Θ(n). Стоимостью `append` будем считать 1 за запись плюс число скопированных элементов. При начальной ёмкости 1 расширение m → 2m происходит на (m + 1)-й операции.

**Определение.** Амортизированная стоимость операции — такое число a, что любая последовательность из n операций над изначально пустой структурой в сумме стоит не больше n·a.

Отдельная операция может быть дорогой — `append` с расширением стоит Θ(n), — но такие операции редки и заранее оплачены дешёвыми. Говорят: `append` работает за O(1) амортизированно, коротко O(1)*.

Это **не средний случай**: средний случай усредняет время по входным данным и требует вероятностной модели, а амортизированная стоимость усредняется по последовательности операций, вероятностей не требует и гарантирована даже для худшей последовательности.

## 6. Агрегатный метод и метод учёта

**Определение.** Агрегатный метод — способ амортизированного анализа, при котором суммарную стоимость T(n) любой последовательности из n операций оценивают сверху целиком, а амортизированную стоимость одной операции считают равной T(n)/n.

Пусть сделано n операций `append` при начальной ёмкости 1, и 2ᵏ — ёмкость перед последним расширением. Это расширение произошло на (2ᵏ + 1)-й операции, поэтому 2ᵏ < n:

```
Записи:       n
Копирования:  1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1    ← сумма прогрессии
              < 2·2ᵏ < 2n
Всего:        < n + 2n = 3n
На операцию:  < 3 = O(1)
```

Пример при n = 17: число копирований равно 1 + 2 + 4 + 8 + 16 = 31 < 2·17 = 34, а полная стоимость — 17 + 31 = 48 < 3·17 = 51.

**Определение.** Метод учёта — способ амортизированного анализа, при котором каждой операции назначают фиксированную плату; излишек сверх фактической стоимости откладывают в копилку и из неё оплачивают дорогие операции. Копилка не должна уходить в минус.

В русском переводе учебника Кормена и др. (гл. 17) агрегатный метод называется групповым анализом, метод учёта — методом бухгалтерского учёта, а накопленный излишек — кредитом; в КИМ-02 метод учёта назван банковским.

Стоимость будем измерять в монетах: одна монета оплачивает одну запись или одно копирование элемента. Каждый `append` платит 3 монеты: одна идёт на запись своего элемента, две откладываются в копилку. Расширение m → 2m копирует m элементов и оплачивается из копилки: при начальной ёмкости c₀ каждое расширение, кроме первого, оплачивают m/2 элементов, добавленных после предыдущего расширения (m/2 · 2 = m монет), а первое — все c₀ элементов начального буфера.

Каждое расширение оплачено полностью, поэтому копилка никогда не уходит в минус; значит, фактическая стоимость любых n операций не превышает внесённой платы 3n. В заготовке ЛР 2 начальная ёмкость 4: после каждого расширения в копилке остаётся c₀ + 2 = 6 монет (при c₀ = 1 было бы 3), и выводы те же.

## 7. Почему ёмкость удваивают

При росте на константу k расширения копируют k, 2k, …, Jk элементов, где J ≈ n/k. Всего это k·(1 + 2 + … + J) = k·J·(J + 1)/2 ≈ k·(n/k)²/2 = n²/(2k) копирований, то есть Θ(n) на операцию при постоянном k.

Если же ёмкость растёт в q раз (q > 1) и c < n — ёмкость перед последним расширением, то прежние ёмкости не больше c/q, c/q², …, и общее число копирований не больше c·(1 + 1/q + 1/q² + …) = c·q/(q − 1) < n·q/(q − 1) (в скобках — сумма геометрической прогрессии со знаменателем 1/q). Любой множитель q > 1 даёт O(1) амортизированно.

Если при удалениях буфер сжимают вдвое, делать это нужно, когда он заполнен на четверть, а не наполовину: иначе чередование `append` и `pop` на границе стоит Θ(n) на операцию.

## 8. Связные списки

**Определение.** Связный список — последовательность узлов, в которой каждый узел хранит значение и ссылку на следующий (в двусвязном — и на предыдущий); порядок задают ссылки, а не расположение в памяти.

В односвязном списке узел — пара (value, next), а список задан ссылками head на первый узел и tail на последний. Вставка в начало, в конец через tail и после известного узла стоит Θ(1), доступ по индексу и поиск — Θ(n). Удаление последнего узла стоит Θ(n) даже с tail: нужно найти предпоследний узел, поэтому дек строят на двусвязном списке.

В двусвязном списке узел хранит ещё prev, и удаление узла по ссылке на него стоит Θ(1). **Фиктивный узел** (sentinel) без данных замыкает список в кольцо: у каждого узла всегда есть оба соседа, и проверки на `None` не нужны.

```python
def insert_after(p, node):
    node.prev = p
    node.next = p.next
    p.next.prev = node   # сначала сосед
    p.next = node        # потом p

def remove(node):
    node.prev.next = node.next
    node.next.prev = node.prev
```

Порядок важен: если сначала выполнить `p.next = node`, строка `p.next.prev = node` испортит `node.prev`, а старый сосед останется ссылаться на p.

| Операция | Динамический массив | Двусвязный список |
| --- | --- | --- |
| Доступ по индексу i | Θ(1) | Θ(n): проход по ссылкам |
| Вставка и удаление в начале | Θ(n): сдвиг всех элементов | Θ(1) |
| Вставка и удаление в конце | O(1) амортизированно | Θ(1), если хранить tail |
| Вставка в середину по номеру позиции | Θ(n): сдвиг хвоста | Θ(n): поиск позиции |
| Вставка и удаление по ссылке на узел | — | Θ(1) |

По замеру в 64-битном CPython 3.13 ссылка в `list` занимает 8 байт, а узел со `__slots__` — 56 байт. Узлы к тому же разбросаны по памяти, и каждый переход по ссылке может дать промах кэша процессора. Поэтому по умолчанию выбирают массив, а список — когда вставки и удаления выполняются по уже известным ссылкам на узлы.

## 9. Стек, очередь и дек

**Определение.** Абстрактный тип данных (АТД) — набор операций вместе с контрактом, описывающим их поведение, без указания способа реализации; у одного АТД может быть несколько реализаций.

**Определение.** Стек — АТД с дисциплиной LIFO («последним пришёл — первым ушёл»): элементы добавляются и извлекаются с одного конца — вершины.

Операции `push(x)`, `pop()`, `peek()` и `is_empty()` стоят Θ(1); если стек построен на динамическом массиве, `push` стоит O(1) амортизированно. По контракту `pop()` и `peek()` пустого стека выбрасывают `IndexError`, а не возвращают `None`.

**Определение.** Очередь — АТД с дисциплиной FIFO («первым пришёл — первым ушёл»): элементы добавляются в конец, а извлекаются из начала.

**Определение.** Дек (двусторонняя очередь) — АТД, в котором добавлять и извлекать элементы можно с обоих концов.

Дек с операциями на концах за Θ(1) строят на двусвязном списке или на кольцевом буфере — массиве ёмкости capacity, где i-й элемент дека лежит в ячейке (head + i) mod capacity (mod — остаток от деления), а head — индекс первого элемента. Концы дека «перетекают» через край массива; если заполненный буфер расширять, операции на концах стоят O(1) амортизированно.

Очередь на `list` с `pop(0)` — ловушка: удаление первого элемента сдвигает все остальные элементы — Θ(n) на операцию. В Python для очереди есть `collections.deque` — двусвязный список блоков по 64 ссылки.

| Операция | `list` | `collections.deque` |
| --- | --- | --- |
| В начале: `insert(0, x)` и `pop(0)` против `appendleft(x)` и `popleft()` | Θ(n) | Θ(1) |
| Индексация в середине: `a[n // 2]` | Θ(1) | Θ(n) |

## 10. Связь с лабораторной работой № 2

В [лабораторной работе № 2](../M1-intro-and-basic-structures/kim-02-recursion-linear-structures.md) нужно реализовать рекурсивные функции, `DynamicArray`, `Stack` и `Deque`, сравнить их с `list` и `collections.deque` и провести амортизированный анализ методом учёта.

Верификация ([`docs/ai-verification.md`](../docs/ai-verification.md)) — это инварианты (size ≤ capacity, рост ёмкости ×2, LIFO, FIFO), тесты (пустая структура, один элемент, опустошение и повторное наполнение, серия операций через границу роста ёмкости) и сверка с `list` и `collections.deque` на операциях своего варианта. Данные варианта генерирует команда `python scripts/generate_data.py --variant N --only ops`; в них структуры многократно опустошаются и встречаются операции над пустой структурой.

Если при удалении последнего узла забыть обнулить tail, ошибка проявится, только когда структуру опустошат и снова наполнят: после `push_back(1)`, `pop_front()`, `push_back(2)` вызов `pop_front()` должен вернуть 2.

Срезы в рекурсии, `pop(0)` в очереди и рост ёмкости на 1 вместо удвоения дают верные ответы, поэтому тесты на правильность их не ловят. Такие дефекты выявляет оценка сложности: вывод асимптотики, счётчик копирований и замеры на данных своего варианта ([`docs/reproducibility.md`](../docs/reproducibility.md)).

## Вопросы для самопроверки

1. Сколько вызовов делают наивный fib(6) и fib_memo(6) из заготовки ЛР 2 и какова наибольшая глубина стека?
2. Чем амортизированная стоимость отличается от стоимости в среднем случае?
3. Почему очередь на `list` с `pop(0)` работает медленно и чем её заменить?

<details>
<summary>Ответы</summary>

1. Наивный fib(6) делает C(6) = 2·F(7) − 1 = 2·13 − 1 = 25 вызовов, `fib_memo(6)` — 2·6 − 1 = 11 (счётчик заготовки учитывает и попадания в кэш). Наибольшая глубина стека у обеих версий — 6 кадров: fib(6) → fib(5) → … → fib(1).
2. Средний случай усредняет время по входным данным и требует вероятностной модели; амортизированная стоимость усредняется по последовательности операций, вероятностей не требует и гарантирована даже для худшей последовательности.
3. `pop(0)` сдвигает все оставшиеся элементы — Θ(n) на операцию. Вместо `list` нужен `collections.deque` с `popleft()` за Θ(1).
